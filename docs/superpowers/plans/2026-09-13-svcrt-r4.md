# svcrt R4 — attribute ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move each attribute key to the module that emits it, and move the access-log middleware to `httpserver`, so no module names a concept it does not produce.

**Architecture:** Four tasks, each self-contained and each leaving `./scripts/ci.sh` green. No new behaviour: two constants are deleted, five move, one middleware moves packages and gains a name. The consumer (`examples/orders`) is updated inside the task that breaks it, never afterwards.

**Tech Stack:** Go 1.25 (`contract` is go 1.22), stdlib only. No new dependencies in any direction.

**Spec:** `docs/superpowers/specs/2026-09-13-svcrt-r4-design.md`

## Global Constraints

- Every library module keeps **zero `require` directives**. This refactor must not create an intra-project import in either direction — that is the point of it.
- `contract` must keep importing **only `context`**. It is `go 1.22, zero requires, forever`.
- 100% statement coverage on library modules; mutation floors hold for every touched module.
- `GOWORK=off go vet ./...` exit 0 in every module. `go test` runs only a vet subset excluding `copylocks`.
- `gofmt -l .` silent; `./scripts/ci.sh` exit 0 at the end of **every** task, not just the last.
- **This is a pure-move refactor. A moved test that needs rewriting to pass is evidence the move changed behaviour** — stop and report rather than adapting the test.
- Commit before any experiment ending in `git checkout --` (`docs/conventions.md` §10).

- [ ] **Step 1: Add the constant to `contract`**

// KeyCode is the well-known log attribute key for a Coded error's code.

// It lives here rather than in a logging package because it names this

// returns. A server-side log line and a client-side error can then be joined

## Task 3: Move the access-log middleware and its keys to `httpserver`

**Files:**
- Create: `httpserver/accesslog.go`, `httpserver/accesslog_test.go`
- Delete: `logging/middleware.go`, `logging/middleware_test.go`
- Modify: `logging/logging.go`, `httpserver/middleware.go`, `httpclient/middleware.go`, `examples/orders/server.go`, `examples/orders/server_test.go`

**Interfaces:**
- Consumes: nothing from Tasks 1–2.
- Produces: `httpserver.AccessLog(l *slog.Logger) Middleware`, and `httpserver.KeyMethod`, `KeyRoute`, `KeyStatus`, `KeyDurMS`. `logging.Middleware` and those four keys cease to exist.

This is the largest task. Spec §3.

- [ ] **Step 1: Move the files with git, so history follows them**

```bash
git mv logging/middleware.go httpserver/accesslog.go
git mv logging/middleware_test.go httpserver/accesslog_test.go
```

Using `git mv` rather than create-and-delete keeps `git log --follow` working on the moved code, which matters for a file whose comments record real incidents.

- [ ] **Step 2: Adjust the moved implementation**

In `httpserver/accesslog.go`:

1. Change `package logging` to `package httpserver`.
2. Rename the function `Middleware` to `AccessLog`, and change its return type from `func(http.Handler) http.Handler` to `Middleware` — that is this package's own named type, declared in `middleware.go`. A constructor returning its own package's type is the whole point of the move.
3. Move the four key constants into this file, from `logging/logging.go`:

```go
// Well-known attribute keys for the access log.
//
// Log output is consumed by a node agent with a schema contract, so these
// names are part of the interface rather than free-form text (12-factor XI,
// amended).
//
// They live here rather than in a logging package because AccessLog is what
// emits them: method and route come from the request, status and duration
// from serving it. A module that does not produce an attribute should not be
// naming it.
const (
	KeyMethod = "method"
	KeyRoute  = "route"
	KeyStatus = "status"
	KeyDurMS  = "duration_ms"
)
```

4. Update the doc comment on `AccessLog` so it names the new function. **Do not rewrite its body or its existing comments** — the paragraph explaining why the route comes from `r.Pattern` rather than the raw path, and the one explaining why the panic is deliberately not recovered, are both records of real reasoning and must survive verbatim.

- [ ] **Step 3: Adjust the moved test**

In `httpserver/accesslog_test.go`: change the package clause to `package httpserver_test`, change every `logging.Middleware(` to `httpserver.AccessLog(`, and repoint every `logging.KeyX` to `httpserver.KeyX`. Fix the import block accordingly.

**Change nothing else.** Per the Global Constraints, a moved test that needs its assertions rewritten is evidence the move changed behaviour — stop and report if you find yourself doing that.

- [ ] **Step 4: Empty out `logging`'s key block**

Tasks 1 and 2 removed three of the seven constants; this task removes the remaining four. The `const (...)` block in `logging/logging.go` is now empty — **delete the block and its doc comment entirely**, rather than leaving an empty one.

Then amend the package doc, which currently claims something no longer true:

```go
// Package logging provides a slog.Handler that enriches records from their
// context.
//
// It is not a logging framework and not a wrapper: the logger it returns is a
// plain *slog.Logger, and everything it produces is ordinary slog output.
//
// It defines no attribute keys. A key belongs to whichever module emits the
// attribute -- httpserver names the access-log keys, contract names the error
// code, telemetry names the trace ids -- and this package never learns what
// any of them mean. That is the same separation the Extractor seam exists for.
package logging
```

The first line must lose "plus the attribute-key conventions svcrt services share".

- [ ] **Step 5: Fix the two cross-module doc comments that now name a dead symbol**

`httpserver/middleware.go:9` and `httpclient/middleware.go:14` both describe the project's `Middleware` spellings and both name `logging.Middleware`, which no longer exists. Amend each to describe the three that remain — `contract.Middleware` (generic, call-level), `httpserver.Middleware` (wraps `http.Handler`), `httpclient.Middleware` (wraps `http.RoundTripper`) — and drop the constructor entry.

These are comments describing a convention; leaving them naming a deleted symbol is exactly the defect this project treats most seriously.

- [ ] **Step 6: Repoint the consumer**

`examples/orders/server.go:100` currently reads:

```go
	return logging.Middleware(log)(mux)
```

Change it to:

```go
	return httpserver.AccessLog(log)(mux)
```

Add the `httpserver` import if absent, and drop the `logging` import if nothing else in the file uses it. In `examples/orders/server_test.go`, repoint `logging.KeyRoute` and `logging.KeyStatus` to `httpserver.KeyRoute` / `httpserver.KeyStatus`, fixing imports the same way.

- [ ] **Step 7: Run everything**

Run:
```bash
cd logging && GOWORK=off go vet ./... && GOWORK=off go test ./... && go test -cover ./...
cd ../httpserver && GOWORK=off go vet ./... && GOWORK=off go test -race -count=10 ./... && go test -cover ./...
cd ../examples/orders && go vet ./... && go test -race ./...
cd ../.. && ./scripts/ci.sh
```
Expected: all PASS, `ci.sh` exit 0.

- [ ] **Step 8: Confirm `logging` no longer touches HTTP**

```bash
grep -rn 'net/http' logging/*.go | grep -v '_test.go' || echo "clean"
```

Expected: `clean`. This is the spec's §3 claim and the most visible evidence the move landed: `logging`'s imports should now be `context`, `io`, `log/slog`, `slices`, `time`.

- [ ] **Step 9: Prove the move changed no behaviour**

Run the mutation gate on both ends, since a moved middleware that lost an assertion shows up as a survivor even when the diff reads as pure relocation:

**Type consistency.** `AccessLog`, `Middleware`, `KeyMethod`, `KeyRoute`, `KeyStatus`, `KeyDurMS`, `KeyCode` are spelled identically throughout. `AccessLog` returns `httpserver.Middleware` (the in-package named type) — which does **not** conflict with the R3 rule about unnamed return types, because that rule governs middleware built for *another* module's named type. Same-package is the case the rule exists to contrast with, and Task 4 Step 1 says so.

**One thing this plan adds beyond the spec.** The spec did not mention that `httpserver/middleware.go` and `httpclient/middleware.go` both name `logging.Middleware` in their doc comments, or that `logging`'s package doc and the README advertise key conventions it will no longer have.
